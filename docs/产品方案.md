# 期货量化模拟平台｜产品与工程方案

## 1. 产品定位

面向量化策略研究者、期货交易者及专家评审的本地 paper trading 项目。通过一条常见的 5 分钟均线金叉/死叉策略链路，展示策略配置、历史/模拟行情回放、虚拟成交、品种状态诊断、交易复盘及每日模拟盘诊断。

**范围边界：**当前只接受用户导入且有权使用的离线历史行情，或后续接入的授权模拟行情；不连接券商、实盘账户，不发送真实委托，不提供收益保证。前端现有业务数据全部由本机服务端 API 提供，并保存在 SQLite。

## 2. 目标用户与核心流程

1. 用户打开仪表盘，先看到模拟账户权益、当日盈亏、回撤、信号和风险提示。
2. 选择品种与 5 分钟周期，在策略实验室调整均线窗口及技术指标过滤条件。
3. 启动/暂停本地模拟策略，查看图表上的信号标记及策略状态。
4. 在品种诊断页查看趋势、波动、成交活跃度、信号质量和适用性说明。
5. 在交易清单逐笔复盘入场/出场时间、价格、费用、盈亏、信号原因与退出原因。
6. 查看每日模拟盘诊断，了解表现、风险、数据覆盖与下一步检查项；向问答助手询问规则或指标定义。

## 3. 页面结构

- **总览 / 仪表盘：**核心 KPI、**自选品种实时 K 线**（板块 → 品种 → 周期，9 个周期：1m/5m/15m/30m/60m/4h/12h/1d/1w，跟随所选品种滚动）、权益曲线、最新模拟信号、最近交易、当日诊断摘要。
- **策略实验室（策略库）：**品种/周期、快慢均线、可选 RSI/MACD/布林带/ATR 过滤、仓位风险上限、参数校验；**品类与品种都是可搜索的选择器**（精确匹配代码/中文名，模糊匹配名称包含、板块、交易所、拼音首字母与英文别名；品类可反查含某品种的板块，策略列表也支持按策略名/品种/品类过滤）；**每条策略独立启停常驻纸上交易**（启动 / 暂停 / 恢复 / 停止，卡片内显示状态、持仓与盈亏，服务端每 15 秒跟一次行情）；**点「详细」弹出该策略的交易记录**——常驻 / 区间模拟 / 回测成交逐笔汇总，含每笔毛盈亏、费用、净盈亏、收益率、持仓时长与退出原因，附汇总统计与来源构成；**AI 调参**：一句话说明诉求 → 模型给出「参数 当前 → 建议 + 理由」→ 弹窗逐条确认后才写库。
- **两种跑法共用一套引擎：**区间模拟给定一段行情一次跑完；常驻交易增量喂行情、持续判定。后者只是 `continuous=True` + `feed()` 的差别，撮合口径不分叉。
- **品种诊断（消息面为主体）：**先选品种（品类与品种都可搜索），页面自动加载 **CBOE 官方 VIX 恐慌指数**（数值 / 日期 / 1·5·20 日变化 / 近一年分位 / 分级 / 30 日走势）、跨市场避险线索（COMEX 黄金白银原油铜、美元指数、中美股指）、**品种定向快讯**（SHMET 分类 + 板块/宏观关键词，带偏多偏空与线索类型）、今日高重要性财经事件、资金行为与供需，以及六个分量可逐条复算的**复合情绪温度**（0–100）。技术面收进默认折叠的「速览」，点「算技术面」才展开。**AI 诊断**按消息面为主的六段骨架解读（消息面主线 / 恐慌指数与跨市场避险 / 情绪温度与资金行为 / 供需库存与事件日历 / 技术面交叉校验 / 变量与数据缺口），前四节篇幅不低于 65%；范围可切「只看消息面」「只看技术面」。本页只呈现所选品种的数据，不混入模拟盘回放统计。
- **交易（区间模拟）：**选策略 + 行情来源 + 品种/合约 + 时间段一次跑完，输出买卖点、逐笔盈亏、按日汇总；右侧可切实盘（未接入）。
- **实时 K 线：**CTP(SimNow) 真实行情或内置模拟源 → tick 合成多周期 K 线；**交易点默认隐藏**，点「交易详情」中的某笔才在图上单独标出该笔开平仓。
- **交易清单：**汇总各策略运行的模拟成交，展示策略、品种、方向、开平时间、价格、费用和净盈亏。
- **每日 AI 诊断：**每个交易日一份复盘，固定五段：今日概览 / 妙手 / 失误点 / 策略改进建议 / 明日观察；支持导出 Markdown 与 HTML。页面上的 KPI 卡片是服务端直接算出的口径，正文是模型基于同一批成交写的解读。
- **智能问答：**限定在策略说明、指标定义、模拟数据、已发生的表现分析；可解释原因、给参数改进方向，但不预测收益、不给买卖建议。**模型由服务端绑定，页面不提供任何 AI 配置入口**，只读显示当前生效的模型名。

## 4. 指标与策略配置

基准策略：5 分钟收盘价的快均线向上穿越慢均线时产生多头入场信号，向下穿越时平多并可选反手做空。原型默认仅演示信号和虚拟成交。配置至少包含：

- 均线类型（SMA/EMA）、快线和慢线周期、信号确认方式、是否允许做空。
- 常用指标开关与参数：RSI 周期/阈值，MACD 快慢线/信号线，布林带周期/倍数，ATR 周期/波动过滤阈值。
- 仿真参数：初始虚拟资金、每笔风险预算、最大持仓/手数、手续费、滑点、单日止损与最大回撤停机线。
- 参数校验：快线必须短于慢线；样本长度不足时不生成信号；对未来数据泄漏、过拟合、手续费/滑点敏感性给出提醒。

## 5. 交易记录字段

每条记录至少保存：模拟交易 ID、策略版本/参数快照、品种、合约代码、周期、方向、开/平仓时间与价格、数量、手续费、滑点、毛盈亏、净盈亏、持仓时长、入场/出场信号、退出原因、成交/未成交状态、数据来源/时间戳。期货盈亏需按品种乘数和合约规则计算；跨合约换月、涨跌停、夜盘和保证金模型应在正式仿真引擎中单独处理，不能用通用假设代替。

## 6. 诊断逻辑

- **品种诊断：**消息面与情绪的每条线索都由服务端抓好再交给模型——VIX 来自 CBOE 官方日线，情绪温度按公开公式加权（分量、取值、权重、缺失项全部对读者可见），快讯倾向来自关键词词典，模型不参与任何计算，只做"把事实串成叙事"，且必须为每个结论标注依据数字与日期、区分事实与推断。技术面以**所选品种自己**的主力连续分钟线为样本窗口（区间涨跌与位置、均线排列与 MA20 斜率、ADX/+DI/−DI、ATR、量能比、跳空、关键位置），只作为第五节的交叉校验；样本不足（<60 根）直接报错说明，主力连续的换月跳空必须标注，不能外推成长周期结论。**口径底线**：情绪温度是本地复合代理指标，不是 CBOE VIX；VIX 才是真实指数；快讯词典不是语义判断；任一数据源失败只标「未获取」，绝不补数字或补新闻。
- **策略诊断：**拆分多空、时段、趋势/震荡区间表现；报告毛/净收益、手续费/滑点影响、最大回撤、连续亏损、持仓暴露及参数扰动表现。
- **每日模拟盘诊断：**核对数据缺口/延迟、信号到模拟成交链路、当日净盈亏与回撤阈值、异常成交价、持仓状态、费用记账和策略版本。输出事实、可能原因、建议复核动作；不自动修改参数。
- 所有统计要展示统计区间、样本量、数据来源与计算口径；回测/模拟表现不代表未来结果。

## 7. 技术架构建议

**当前实现：**静态前端（`web/`）由 Python 标准库 HTTP 服务同源托管，且只放行白名单后缀与 `web/` 目录内的文件（`.env`、源码、数据库一律不可达）；后端按职责拆包于 `app/`：`api.py` 路由与鉴权、`engine.py` 统一策略引擎（信号判定 + 撮合记账，回测与模拟盘共用同一条路径）、`backtest.py` 按时间区间取数 + 切分与统计、`history.py` 真实历史行情（日线任意日期区间 / 分钟线可得窗口校验）、`simulate.py` 区间模拟、`trading.py` 多运行推进、`db.py` SQLite 持久化、`views.py` 仪表盘与诊断、`feed.py` 实时行情聚合与 SSE、`instruments.py` 品种合约元数据（乘数/最小变动/保证金/主力月份，67 个品种）、`ai.py` 问答与 JSON 补全、`aistrategy.py` AI 调参提案、`macro.py` 环境分析、`report.py` 每日诊断、`klines.py` 按需 K 线（9 周期）、`ticks.py` 秒级实时 tick 与形成中 bar 合成、`simnow.py` 可选的 CTP 行情网关。浏览器仅调用 API，不提供伪造数据兜底。策略 CRUD、回测保存/读取、模拟盘、仪表盘、诊断、环境分析、每日报告均使用同一服务端状态。

**行情边界：**实时行情**只读订阅**——CTP(SimNow) 通道仅连接与订阅 tick，不下发任何委托；未连柜台时可用内置模拟源验证链路，模拟 bar 与真实 bar 按 `source` 严格隔离、不混画。仪表盘的自选 K 线走 akshare 的**主力连续**行情（非具体月份合约，有换月跳空与价差），支持 9 个周期：1m~60m 取新浪原生 N 分钟窗口，4h/12h 由 60 分钟线合并，1d/1w 走真实日线（周线按自然周合并）；**所有周期按秒实时监听**——SSE 秒级流（`/api/kline/stream`）先推全量窗口，之后每秒推「实时 tick 合成的形成中 bar」，正在走的蜡烛逐秒跳动（快照约 1 秒 1 次，非逐笔），流不可用时自动降级轮询对应周期的真实 K 线，避免口径错位。它与实时页的 tick 级行情是两条不同的数据链路，界面上分别标注。**回测是第三条链路**：页面只提交品种 / 起止日期 / 周期，服务端按时间区间拉公开真实历史行情（日线任意历史日期；分钟线受上游最近约 1023 根限制，超窗口明确报错并给出可用起点，绝不静默换成合成数据），结果与数据源、区间、覆盖信息一并落库；它是模拟撮合的历史回放，不是实时实盘，不发真实委托。问答支持 DeepSeek 或 GLM；**API Key 只从服务端 `.env` 读取**，页面不提供服务商 / 模型 / Key 任何配置入口，Key 不写入数据库、不下发浏览器；不配置时三处 AI 功能各自明确提示"未配置"，其余功能照常可用。`data/legacy/` 下的旧 JSON 文件保留为未导入的历史备份，避免未经核验的演示数据进入新账本。

**后续可演进架构：**前端（策略配置、图表、复盘）→ API 服务（身份/权限、参数校验、审计）→ 行情适配层（授权数据、时区/交易时段、合约连续化）→ 事件驱动回测/模拟撮合引擎（订单状态机、费用/滑点/合约乘数、幂等）→ PostgreSQL（策略版本、信号、订单、成交、净值）+ 时序存储/对象存储 → 诊断任务与可解释问答检索层。第一阶段仍应隔离实盘接口；如未来讨论实盘，需独立立项、风控和合规评审。

**显示口径：**全站统一**红涨绿跌**（国内期货习惯）——涨 / 盈利 / 多头 / 主动买为红，跌 / 亏损 / 空头 / 主动卖为绿。唯一色源是 `web/index.html` 的 `--up` / `--down`，K 线蜡烛、成交量柱、买卖标记、盈亏数字与诊断涨跌幅都按此渲染；`--red` / `--green` 仅用于状态与警示标签（如「实时」「已连接」「已暂停」），不表达盈亏；AI 调参的参数变化是中性 diff，用蓝色区分，避免被误读成涨跌。品种诊断的「情绪温度」等级色是**警示刻度**（平稳→恐慌），不代表涨跌方向；快讯「偏多/偏空」标签与跨市场涨跌幅仍按 `--up` / `--down` 渲染。

## 8. 迭代路线

1. **本地纸面验证（当前）：**单品种按时间区间调取真实历史行情、均线策略、ATR/RSI 过滤、服务端历史回测（训练/测试切分）和可暂停模拟回放；CSV 只保留给命令行脚本与自检夹具。
2. **研究验证：**接入授权历史行情，核对期货合约规则；建立换月、时段、保证金、费用/滑点与参数敏感性报告。
3. **可控 paper trading：**接入授权实时行情、服务端模拟撮合、断线恢复、审计、运行监控、数据质量告警与权限管理。继续隔离所有真实下单能力。
4. **专家试用：**用户访谈、指标定义校准、诊断可解释性与安全评审；根据反馈打磨工作流。真实行情和下单能力需独立评审，不属于当前项目。

## 9. 当前工程验收点

- 页面清楚显示历史行情回放、模拟数据与真实行情的区别、以及**无真实下单**的边界。
- 策略 CRUD、服务端回测、区间模拟、交易查询、品种/每日诊断、环境分析、每日报告、问答链路可用；回测页面无本地行情文件入口，结果能追溯品种、周期、时间区间与数据源。
- 图表、指标、交易清单和诊断读取同一份服务端模拟盘数据。
- 盈亏依据**品种表**的乘数与最小变动计算（不再硬编码 300），并明确提示撮合、涨跌停、换月和保证金模型限制。
- AI 产出的参数提案必须经人工确认才入库；乘数、最小变动、滑点属于锁定参数，模型不能改。
- `scripts/smoke_test.py` 覆盖上述链路（当前 116 项），跑在临时数据目录上，不污染真实账本。
