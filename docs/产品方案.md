# 期货量化模拟平台｜产品与工程方案

## 1. 产品定位

面向量化策略研究者、期货交易者及专家评审的本地 paper trading 项目。通过一条常见的 5 分钟均线金叉/死叉策略链路，展示策略配置、历史/模拟行情回放、虚拟成交、品种状态诊断、交易复盘及每日模拟盘诊断。

**范围边界：**当前只接受用户导入且有权使用的离线历史行情，或后续接入的授权模拟行情；不连接券商、实盘账户，不发送真实委托，不提供收益保证。前端现有业务数据全部由本机服务端 API 提供，并保存在 SQLite。

## 2. 目标用户与核心流程

1. 用户打开仪表盘，先看到模拟账户权益、当日盈亏、回撤、信号和风险提示。
2. 选择品种与 5 分钟周期，在策略实验室调整均线窗口及技术指标过滤条件。
3. 启动/暂停本地模拟策略，查看图表上的信号标记及策略状态。
4. 在品种诊断页查看趋势、波动、成交活跃度、信号质量和适用性说明。
5. 在交易清单逐笔复盘入场/出场时间、价格、费用、盈亏、信号原因与退出原因。
6. 查看每日模拟盘诊断，了解表现、风险、数据覆盖与下一步检查项；向问答助手询问规则或指标定义。

## 3. 页面结构

- **总览 / 仪表盘：**核心 KPI、权益曲线、最新模拟信号、最近交易、当日诊断摘要。
- **策略实验室：**品种/周期、快慢均线、可选 RSI/MACD/布林带/ATR 过滤、仓位风险上限、参数校验与启停。
- **品种诊断：**趋势/波动/活跃度标签、规则化解释、样本范围和数据质量提示。
- **交易：**从策略库启动多个相互独立的纸面策略运行，逐条查看状态、资金、进度与持仓，并可单独取消。
- **交易清单：**汇总各策略运行的模拟成交，展示策略、品种、方向、开平时间、价格、费用和净盈亏。
- **每日诊断：**盈亏归因、回撤、连续亏损、成本占比、风险事件和待检查事项。
- **智能问答：**限定在策略说明、指标定义、模拟数据和风险教育；回答展示依据/限制，不作为交易建议。

## 4. 指标与策略配置

基准策略：5 分钟收盘价的快均线向上穿越慢均线时产生多头入场信号，向下穿越时平多并可选反手做空。原型默认仅演示信号和虚拟成交。配置至少包含：

- 均线类型（SMA/EMA）、快线和慢线周期、信号确认方式、是否允许做空。
- 常用指标开关与参数：RSI 周期/阈值，MACD 快慢线/信号线，布林带周期/倍数，ATR 周期/波动过滤阈值。
- 仿真参数：初始虚拟资金、每笔风险预算、最大持仓/手数、手续费、滑点、单日止损与最大回撤停机线。
- 参数校验：快线必须短于慢线；样本长度不足时不生成信号；对未来数据泄漏、过拟合、手续费/滑点敏感性给出提醒。

## 5. 交易记录字段

每条记录至少保存：模拟交易 ID、策略版本/参数快照、品种、合约代码、周期、方向、开/平仓时间与价格、数量、手续费、滑点、毛盈亏、净盈亏、持仓时长、入场/出场信号、退出原因、成交/未成交状态、数据来源/时间戳。期货盈亏需按品种乘数和合约规则计算；跨合约换月、涨跌停、夜盘和保证金模型应在正式仿真引擎中单独处理，不能用通用假设代替。

## 6. 诊断逻辑

- **品种诊断：**基于选定样本窗口计算趋势方向与强度、实现波动率/ATR、成交活跃度、信号次数、胜率、盈亏比、成本敏感性、最大回撤和样本量。标签须附规则化原因，例如“近 20 根 5 分钟 bar 波动偏高”；不足样本显示“证据不足”。
- **策略诊断：**拆分多空、时段、趋势/震荡区间表现；报告毛/净收益、手续费/滑点影响、最大回撤、连续亏损、持仓暴露及参数扰动表现。
- **每日模拟盘诊断：**核对数据缺口/延迟、信号到模拟成交链路、当日净盈亏与回撤阈值、异常成交价、持仓状态、费用记账和策略版本。输出事实、可能原因、建议复核动作；不自动修改参数。
- 所有统计要展示统计区间、样本量、数据来源与计算口径；回测/模拟表现不代表未来结果。

## 7. 技术架构建议

**当前实现：**静态前端（`web/`）由 Python 标准库 HTTP 服务同源托管，且只放行白名单后缀与 `web/` 目录内的文件（`.env`、源码、数据库一律不可达）；后端按职责拆包于 `app/`：`api.py` 路由与鉴权、`engine.py` 统一策略引擎（信号判定 + 撮合记账，回测与模拟盘共用同一条路径）、`backtest.py` 切分与统计、`trading.py` 多运行推进、`db.py` SQLite 持久化、`views.py` 仪表盘与诊断、`ai.py` 问答、`simnow.py` 可选的 CTP 行情网关。浏览器仅调用 API，不提供伪造数据兜底。策略 CRUD、回测保存/读取、模拟盘逐 bar 回放与账本、仪表盘、品种/每日诊断均使用同一服务端状态。问答支持 DeepSeek 或 GLM；API Key 由环境变量或问答页送入，仅保存在服务进程内存，不写入数据库、不回传浏览器。系统不接实时行情、不连接券商或真实交易接口。`data/legacy/` 下的旧 JSON 文件保留为未导入的历史备份，避免未经核验的演示数据进入新账本。

**后续可演进架构：**前端（策略配置、图表、复盘）→ API 服务（身份/权限、参数校验、审计）→ 行情适配层（授权数据、时区/交易时段、合约连续化）→ 事件驱动回测/模拟撮合引擎（订单状态机、费用/滑点/合约乘数、幂等）→ PostgreSQL（策略版本、信号、订单、成交、净值）+ 时序存储/对象存储 → 诊断任务与可解释问答检索层。第一阶段仍应隔离实盘接口；如未来讨论实盘，需独立立项、风控和合规评审。

## 8. 迭代路线

1. **本地纸面验证（当前）：**单品种导入 CSV 行情、均线策略、ATR/RSI 过滤、手动事件禁入标记、服务端历史回测和可暂停模拟回放。
2. **研究验证：**接入授权历史行情，核对期货合约规则；建立换月、时段、保证金、费用/滑点与参数敏感性报告。
3. **可控 paper trading：**接入授权实时行情、服务端模拟撮合、断线恢复、审计、运行监控、数据质量告警与权限管理。继续隔离所有真实下单能力。
4. **专家试用：**用户访谈、指标定义校准、诊断可解释性与安全评审；根据反馈打磨工作流。真实行情和下单能力需独立评审，不属于当前项目。

## 9. 当前工程验收点

- 页面清楚显示历史行情回放、无实时行情与无真实下单边界。
- 策略 CRUD、服务端回测、模拟盘回放、交易查询、诊断和问答链路可用。
- 图表、指标、交易清单和诊断读取同一份服务端模拟盘数据。
- 费用和盈亏依据用户输入的合约参数估算，并明确提示撮合、涨跌停、换月和保证金模型限制。
