# 期策 · 本地期货量化纸面模拟平台

一个可以完整跑通的量化 demo：**选策略 + 选时间段 → 区间模拟出一段盈亏 → 回测对照 → 仪表盘 / 诊断 / 问答**，全部落库在本地 SQLite，浏览器只做展示与交互。

不接券商、不发真实委托。交易页提供「模拟盘 / 实盘」切换：模拟盘是**按区间一次跑完的策略模拟**（行情可以是服务端合成的演示数据，也可以接本机 CTP 采集的真实分钟 K 线）；实盘页签目前只展示接入前置条件，不连接任何柜台，也不会发出委托。

## 快速开始

最简单的方式：**双击项目根目录的 `run.bat`**。首次运行会自动装好 `.venv`，然后起服务并自动打开浏览器（`Ctrl+C` 停止）。想换端口就直接带参数：`run.bat 9000`。

命令行方式：

```powershell
# 1) 首次安装（创建 .venv，装 python-dotenv + akshare）
.\scripts\install.ps1

# 2) 编辑 .env 填入 API Key（可留空：AI 问答不用就不填，其余功能照常可用）
notepad .env

# 3) 启动（-Port 9000 换端口，-NoOpen 不自动开浏览器，-Verbose 输出调试日志）
.\scripts\run.ps1
```

浏览器打开 <http://127.0.0.1:8765>。健康检查：<http://127.0.0.1:8765/api/health>。`Ctrl+C` 停止。

> **重复双击不会报错**：如果端口上已经有一个本服务实例在跑，`run.bat` 会认出它、复用并直接打开浏览器（退出码 3，不当作失败）；只有端口被**别的程序**占用时才提示换端口（退出码 1）。要真正重启，先关掉原来那个黑窗口再运行。

> 端口已被占用时会直接报错退出，不会静默复用端口（Windows 上 `SO_REUSEADDR` 允许两个实例绑同一端口，会导致请求随机落到不同数据库连接，这里已显式挡住）。

**回测不需要准备任何行情文件**：在回测页选品种 + 起止日期 + K 线周期，服务端按时间区间拉取**公开真实历史行情**（主力连续）并回放撮合，结果连同数据源、区间、周期一起落库。日线支持任意历史日期；分钟线受上游「最近约 1023 根」限制，超出窗口会明确报错并给出可用起点，绝不静默截断或改用合成数据。交易页的模拟盘仍可用服务端合成的演示行情，选好时间段点「开始模拟」就出买卖点和盈亏。

> 口径提醒：这是**真实历史行情的模拟回放**，不是实时实盘、不发真实委托；主力连续与具体月份合约存在换月跳空/价差，撮合仍不含保证金、涨跌停与真实成交规则。

### 全链路自检

```powershell
.\scripts\smoke_test.ps1
```

它会另起一个临时服务进程（`QICE_DATA_DIR` 指向系统临时目录，**不碰真实账本**），把 194 项断言跑一遍：引擎不变量、建策略、按时间区间的真实历史行情回测、9 周期 K 线口径、秒级 tick 与 SSE 秒级流、逐 bar 推进模拟盘、仪表盘、诊断、问答状态、以及密钥泄露 / 目录穿越 / 跨站请求四类安全回归。联网行情源临时不可用时，相关断言按「明确报错而非静默兜底」降级检查。

命令行也能单独回放（与网页端共用同一个引擎，结果必然一致）：

```powershell
python .\scripts\replay.py data\samples\sample_5m_synthetic.csv --fast 9 --slow 21
```

## 配置（.env）

`.env` 是本机明文，已加入 `.gitignore`，**不要截图或放进共享目录**。服务启动时读取一次，改完需重启。

| 变量 | 说明 |
| --- | --- |
| `AI_PROVIDER` | `deepseek`（默认）或 `glm` |
| `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` | DeepSeek Key 与模型（默认 `deepseek-flash`） |
| `GLM_API_KEY` / `GLM_MODEL` | 选用 GLM 时填写（默认 `glm-5`） |
| `SIMNOW_USERNAME` / `SIMNOW_PASSWORD` | SimNow 模拟账号（**交易页已移除该入口**，仅供后端 `app/simnow.py` 网关使用） |
| `SIMNOW_BROKER_ID` / `SIMNOW_MD_ADDRESS` / `SIMNOW_TD_ADDRESS` | 经纪商代码、行情前置、交易前置 |
| `SIMNOW_APP_ID` / `SIMNOW_AUTH_CODE` / `SIMNOW_PRODUCT_INFO` | 控制台提供时填写 |

DeepSeek 走官方 OpenAI 兼容接口 `https://api.deepseek.com/chat/completions`，模型标识可能调整，以官方文档为准。

**AI 配置只在服务端。** 页面不提供服务商 / 模型 / API Key 输入框，Key 永远不下发到浏览器；「智能问答」页只读显示当前生效的模型名。要换服务商或换 Key，改 `.env` 里对应变量后重启服务。

也可以完全不写 `.env`：不配 Key 时三处 AI 功能（智能问答 / 每日诊断 / 品种诊断）会明确提示"未配置"，其余功能全部照常可用。交易页已不再提供 SimNow 连接表单，如需该网关请直接调用 `/api/simnow/*`。

### AI 用在哪三处

| 用点 | 端点 | 模型拿到什么 | 产出 | 不给什么 |
| --- | --- | --- | --- | --- |
| 智能问答 | `POST /api/ai/chat` | 当前模拟盘状态、策略库参数、最近报告结论 | 解释性回答 | 不预测点位、不生成策略 |
| 每日诊断 | `POST /api/reports` | 当日成交、费用、盈亏结构 | 五段复盘（Markdown / HTML 可导出） | 不给明日买卖建议 |
| 品种诊断 | `POST /api/diagnostics/instrument/analyze` | 消息面与情绪事实清单（VIX / 跨市场 / 快讯 / 日历 / 资金供需）+ 技术面交叉校验 | 六段诊断，**消息面与情绪占 65% 以上**（消息面主线 / 恐慌指数 / 情绪温度 / 供需日历 / 技术面校验 / 变量与缺口） | 不给目标价、不外推长期趋势、不补清单外的新闻与数字 |

策略库里还有一个轻量用点：**AI 调参**（`POST /api/ai/strategy/draft`），只产出参数提案，必须人工点「确认入库」才写库，且只改白名单参数。

### 业务口径（改代码要同步改这里和页面文案）

- **信号在 bar 收盘确认，下一根 bar 开盘价加减滑点成交**，绝不在信号当根成交。
- 回测在训练/测试切分点**强制平仓**，训练段盈亏不带入测试段。
- 手续费按「每边每手」计，一手来回记两次；`atrMaxPct` 对外用百分数（`0.4` = 0.4%），内部换算成小数。
- 模拟盘每根 bar 只做一件事：用**上一根已收盘 bar** 的信号，在**当前 bar 开盘**撮合。回测与区间模拟都是循环调 `advance()` 跑到结束，逐 bar 回放是每次 HTTP 请求调一次 —— 三条路径结果必然一致。
- **恐慌指数与情绪温度口径**：`context.py` 取的是 **CBOE 官方 VIX 日线**（真指数，标日期与近一年分位）；页面上的「情绪温度 0–100」是**本地按公开公式加权的复合代理指标**，由 VIX 水平与分位、VIX 5 日抬升、品种波动率分位、跨市场避险、快讯偏空程度、资金异动六个分量组成，缺失分量剔除后权重重新归一化 —— **不是 VIX，也不是任何机构发布的恐慌指数**。快讯「偏多/偏空」由关键词词典判定，不是语义模型；情绪温度的等级色是警示刻度，与红涨绿跌的盈亏配色无关。
- **配色是红涨绿跌（国内期货习惯）**：涨 / 盈利 / 多头 / 主动买 = 红，跌 / 亏损 / 空头 / 主动卖 = 绿。全站唯一色源是 `web/index.html` 的 `--up` / `--down`；`.positive` / `.negative`、K 线蜡烛（`web/js/kline-core.js` 会读这两个变量）、买卖标记、诊断涨跌数字都走这套口径。注意 `--red` / `--green` 只表示**状态与警示**（如「实时」「已连接」「已暂停」），不要拿来表示盈亏；AI 调参的参数 diff 也不是涨跌，用中性蓝色 `.param-diff`。

- **回测行情口径**：页面只提交 `range = {symbol, start, end, period}`，由 `app/history.py` 取真实历史行情。日线源 `futures_main_sina` 支持任意日期区间；分钟源 `futures_zh_minute_sina` 每周期固定给最近约 1023 根（1m ≈ 4 个交易日、5m ≈ 3 周、15m ≈ 2~3 个月、60m ≈ 9 个月），**请求区间早于可得窗口就报错并返回 `availableFrom`**，前端提供「按可用区间回测」一键修正。行情按北京时间 +08:00 存 ISO 时间戳（日线记当日 15:00），OHLC 异常行跳过并计入 `warnings`；同一区间 5 分钟缓存。回测结果里 `dataSource / symbol / period / requestedRange / coverage / warnings / notice` 随 `result_json` 一起落库，翻旧记录也能对齐口径。`POST /api/backtests` 仍接受 `bars` 数组，但那是本地自检与旧调用方的兼容入口，页面不再使用。

## 实时 K 线

「实时 K 线」页有两种数据源，都在页面上直接切换：

| 数据源 | 前提 | 延迟 | 用途 |
| --- | --- | --- | --- |
| **CTP（SimNow）** | `.env` 填好 `SIMNOW_*`，或页面点「连接 SimNow 实时行情」 | tick 级 | 看真实期货行情，**只读订阅、不下单** |
| **内置模拟源** | 无 | 可调到 120 倍加速 | 没账号或非交易时段时验证链路 |

- **聚合口径**：tick 按北京时间切 1 分钟窗口，累加 O/H/L/C/V；跨分钟先收口上一根再开新根。5/15/30/60 分钟由 1 分钟合成，只在取数时合并，不重复存储。
- **推送**：SSE（`text/event-stream`），浏览器自带断线重连，服务端 15 秒一次心跳。选 SSE 而不是 WebSocket 是因为只需要单向推送，标准库即可实现、不引入依赖。
- **落库策略**：只把已收口的 bar 写进 `live_bars`（每分钟每合约最多一次写），正在形成的那根只留在内存，避免高频写盘。
- **数据源隔离**：`live_bars.source` 记录每根 bar 来自 `ctp` 还是 `sim`，查询默认只取 `ctp`。模拟源按加速倍数生成 bar，时间戳会跑到当前时刻之后；不隔离的话模拟数据会和真实行情混在一张图上，把坐标轴顶歪、价格画成跳空（这是实际踩到的坑）。v3→v4 迁移里已存在的行无法辨别来源，统一标为 `legacy` 并排除在查询之外——宁可图上少几根，也不能把模拟数据当真实行情。
- **历史不回溯**：CTP 只推实时 tick，接上之后从当前时刻开始攒 K 线，页面对此有明确提示。
- **两处入口**：完整图表在「实时 K 线」页（含周期切换、成交标记、对齐回放）；仪表盘顶部另有一个紧凑版组件，**自带板块 → 品种 → 周期选择器**，跟随所选品种滚动。两者共用 `web/js/kline-core.js` 这一份绘图内核，不会出现口径不一致。

### 仪表盘的 K 线为什么不依赖实时页

仪表盘的 K 线按「周期 + 当前选中的品种」自动切换数据来源，周期下拉共 9 档：**1m / 5m / 15m / 30m / 60m / 4h / 12h / 1d / 1w**，**全部按秒实时监听**：

| 情况 | 数据来源 | 标签 |
| --- | --- | --- |
| **1 分钟**周期 且 采集器正在跑的恰好就是这个品种 | SSE `/api/live/stream`，逐 tick 聚合 | `CTP 实时` / `模拟源 N×` |
| 其他情况（没连 SimNow、选了别的品种、或选了长周期） | SSE `/api/kline/stream` **秒级流**：hello 全量 + 每秒推形成中 bar | `秒级监听` |
| 秒级流不可用时自动降级 | `/api/kline` 轮询兜底（图还能用，只是不再逐秒跳） | `流不可用，已降级轮询` |

- 秒级流的「每秒 bar」是**真实 tick 合成的形成中 K 线**（新浪实时快照 `futures_zh_spot`，约 0.25 秒可达，服务端 0.8 秒缓存）：正在走的那根蜡烛逐秒动，成交量按每秒增量累加，收盘后由真实 K 线窗口回填。行情快照约 1 秒 1 次，**不是逐笔行情**。
- 采集器 SSE 只推 1 分钟 bar，**长周期即使采集器在跑也走秒级流**——把 1m bar 直接画到 4h/1d 图上口径就错了。
- **9 个周期各有各的数据源**：1m~60m 用新浪原生 N 分钟窗口（约 1023 根，所以 60m 也能画出 9 个月而不是 4 天）；4h/12h 由 60m 原生线合并（上游只有 1/5/15/30/60 五档）；1d 是 `futures_main_sina` 真实日线（任意历史日期）；1w 由日线按自然周合并。返回体带 `periodLabel` / `source` / `notice`，口径直接标在图上。
- **取的是主力连续（`RB0` 这种），不是具体月份合约**。换月跳空、远近月价差都会让它和 `rb2601` 的价格对不上，所以界面上刻意只让选品种、不给选月份，并明确标注「主力连续」。
- 历史窗口在整分钟边界之后才更新最后一根，有几十秒延迟；**秒级跳动由实时 tick 合成补上**。要看逐笔级就切到「实时 K 线」页连 CTP。4 小时及以上周期的历史部分是延迟数据。
- 服务端有进程内缓存（tick 0.8 秒、1m 12 秒、分钟窗口 60 秒、日线 300 秒）；轮询兜底间隔也跟周期走（1m~60m 10 秒、4h/12h 30 秒、1d/1w 60 秒），不会把请求连珠炮一样打到上游。
- **买卖点**：每笔成交按 `entryTime` / `exitTime` 映射到 K 线坐标，买点挂在该根最低价下方、卖点挂在最高价上方，带自动避让与边界收敛；一根 bar 不到 2px 时标签退化成圆点，避免文字互相压住。实时页展示的是**实时源**的 K 线，模拟盘跑的是单独回放的区间行情，两者不是同一段数据——实时页会提示，并可「载入某次运行的行情并对齐」。
- **注意**：非交易时段 CTP 不会有新 tick；`IF2503` 这类已交割合约也没有行情，请用当月在交易的合约（如 `IF2612`、`rb2601`）。

## 品类 / 品种怎么选（策略创建）

新建策略时选标的，原来是一个只有 4 个写死选项的 `<select>`（`沪深300股指 · IF2503` 这类假精度合约），和品种表完全脱节。现在换成两个可搜索的选择器：**交易品类** + **交易品种**，数据全部来自 `/api/instruments`（67 个品种 / 8 个板块）。

### 精确匹配和模糊匹配

| 档位 | 命中条件 | 界面标记 |
| --- | --- | --- |
| 精准 | 品种代码完全相等（`rb`）、中文名完全相等（`螺纹钢`） | 绿色「精准 · 交易所」 |
| 代码前缀 | `rb` → 螺纹钢，`jm` → 焦煤 | 排最前，独立「精准匹配」分组 |
| 中文包含 | `螺纹` → 螺纹钢，`菜` → 菜油 / 菜粕 | 按板块分组 |
| 品类 | `黑色`、`农` → 整组 | 按板块分组 |
| 交易所 | `上期所`、`郑商所`、`DCE` → 该所全部品种 | 按板块分组 |
| 品类别名 | 拼音首字母 `nh` / `ys` / `gjs`，英文 `agri` / `ferrous` / `precious` | 按板块分组 |

- **写法会自动归一**：比较前统一小写、去掉数字和符号，所以 `rb2610`、`RB0`、`rb`、`沪深300股指`、`沪深300股指 · IF2503` 都能一次命中。用户从行情软件里复制过来的代码不用手改。
- **「精准匹配」单独置顶**：输入 `j` 时焦炭（代码完全相等）必须排第一。如果只按板块分组渲染，黑色组排在金融组后面，焦炭会被挤到第三屏——这是分组和排序打架的经典坑。
- **英文别名要求 3 个字母以上**（或整词相等）。否则输入 `ag`（白银）会把 `agri` 名下的 16 个农产品全带出来，把真正的白银淹没在噪声里；而 `nh` 这种两位拼音首字母走单独的全等匹配。
- **品类可以反查品种**：在品类框里输入 `螺纹`，会提示「黑色 · 含 螺纹钢」，方便"我只记得品种名，不知道它属于哪个板块"的场景。
- **搜索不受品类限制**：品类选的是「黑色」，输入 `au` 照样能搜到黄金；同板块的结果只是排在分数相同者的前面。否则用户会以为"选完品类就搜不到别的了"。

### 交互细节

- 键盘 `↑` `↓` 移动、`Enter` 确认、`Esc` 关闭；只有一条结果时 `Enter` 直接选中。
- 面板底部一排板块按钮（全部 / 金融 / 黑色 / …）用于快速切换；点「全部」可跨品类浏览 67 个品种。

## 策略常驻交易（每条策略各自启停）

「区间模拟」是一次性跑完一段历史；「常驻交易」是把策略挂在那里，**每来一根新 bar 判一次**，持续产出成交和持仓。

入口在**我的策略库**，每条策略卡片自带一套开关：

| 卡片上的操作 | 含义 |
| --- | --- |
| ▶ 启动策略 | 拉该品种主力连续分钟线，先按策略参数回放最近一段建立状态，然后开始跟随 |
| ⏸ 暂停交易 | 停止判定信号与开平仓；**持仓保留**，浮盈继续跟最新价 |
| ▶ 恢复交易 | 从当前这根 bar 起重新判定。暂停期间错过的信号**不补做**（补做等于没停过），只记一条 `gap` 信号说明跳过了几根 |
| ■ 停止 | 下线并清掉运行态；已产生的成交记录保留 |

几个关键设计：

- **状态在卡片里，不在页头。** 页头原来那个「运行中 / 暂停策略」是写死的装饰按钮，多条策略各处于不同状态时根本没法表达，已删除。
- **两种模式共用同一个引擎。** 常驻交易只是给 `TradingSession` 加了 `continuous=True`（不在最后一根 bar 强制平仓）和增量喂数据的 `feed()`，撮合口径与回测、区间模拟完全一致。
- **服务端每 15 秒推进一次**（`runner.TICK_SECONDS`），前端每 5 秒轮询运行态，且**只在策略库页可见时**轮询，切走就停。
- **重启不自动续跑。** 服务重启意味着中间断了一段行情，直接续跑会把断档前后的价格硬接在一起；所有运行态统一恢复成「已暂停」，等确认后手动恢复。
- **日线策略按 60 分钟近似推进**，并在卡片上明确标注——分钟线接口没有日线数据，这一点不能含糊。

边界：**只做本地记账，不连柜台、不发任何委托。** "启动策略"不会动真实账户一分钱。

## 策略模拟盘（选一段时间，一次跑完）

「交易 → 模拟盘」回答的是一个问题：**这条策略在这段时间里赚了多少、买卖点在哪、每笔持了多久。**

不再需要准备 CSV。选三样东西即可：

| 选择项 | 说明 |
| --- | --- |
| 策略 | 策略库里保存的策略；不选则用内置 EMA(9)/EMA(21) 兜底，第一次打开也能直接出结果 |
| 行情来源 | **演示行情**：服务端按交易时段（09:30–11:30、13:00–15:00，各 120 根 1 分钟 bar）确定性合成，同一日期永远生成同一段走势，用于验证策略与界面；**真实采集**：本机 CTP 采集并落库的分钟 K 线，只能覆盖开始采集之后的时间 |
| 时间段 | 「最近 1 / 3 / 5 / 10 个交易日」快捷按钮，或直接选起止日期；单次最多 20 个交易日（约 4,800 根 bar） |

跑完直接给出四块结果：

1. **KPI**：净盈亏、收益率、胜率、盈亏因子、最大回撤、交易笔数（附手续费合计与单笔期望）；
2. **K 线 + 买卖点**：红点买入开仓、绿点卖出平仓，可切「全部 / 近 1 日 / 近 1 小时」，悬停看成交价与时间；
3. **逐笔明细**：开仓时间/价、平仓时间/价、持仓时长、手数、毛盈亏、费用、净盈亏、收益率、持仓期间最大浮盈/浮亏、退出原因，可导出 CSV；
4. **按交易日盈亏**：当日成交笔数、胜/负、手续费、当日与累计盈亏、日终权益。

实现要点：

- 行情来源由服务端决定，**演示数据与真实采集数据永不混用**（演示固定 `IF-DEMO`，真实按合约名查 `live_bars.source='ctp'`）；
- 演示行情会截止到「现在」：当天没收盘就只生成已经发生的分钟，不会出现未来时间的 bar；
- 真实来源根数不足时直接说清楚缺多少、怎么补，不会跑出一个「0 笔成交」的空结果；
- 结果写进 `trading_runs`（`tradePrefix=SIM`），所以仪表盘、交易清单、诊断都能读到，也能在历史列表里点回来重看。

## 行情 CSV 格式（仅脚本 / 本地自检）

**网页回测已不再使用本地行情文件**，改为按时间区间取真实历史行情。CSV 解析只留给 `scripts/replay.py`（命令行回放）与 `app/marketdata.py`（自检夹具），格式如下。

必需表头 `timestamp,open,high,low,close,volume`，可选 `event_blackout`（`1/true/yes` 标记该 bar 事件禁入）。

- 时间需能被 ISO 8601 解析（如 `2025-02-17T09:00:00+08:00`），**严格递增且不重复**；
- `low ≤ min(open, close) ≤ max(open, close) ≤ high`，数值必须有限，成交量非负；
- 支持 30 – 20,000 根 bar；
- 建议单一合约、统一时区、统一周期，并自行核对夜盘/午休缺口与换月。

## 安全边界

本项目虽然只监听 `127.0.0.1`，但浏览器里的任意网页都能向本机端口发请求，因此做了三层防护：

1. **静态根固定为 `web/`**，且只放行白名单后缀；任何以 `.` 开头的路径（`.env` / `.venv` / `.git`）一律 404。旧实现把项目根当静态根，`GET /.env` 能直接下载到 API Key 和 SimNow 密码。
2. **来源校验**：校验 `Host`（防 DNS rebinding）与 `Origin`（防跨站）。
3. **写操作强制 `Content-Type: application/json`**，跨站表单/图片等简单请求无法伪造该头。

API Key 只在服务端使用，`/api/ai/status` 只回传「是否已配置」，永不回传 Key 本身。

## 已知边界（不要高估结果）

- 只做**单品种、只做多、固定手数**的简化撮合；不模拟保证金、涨跌停、换月、交易时段、盘口冲击、部分成交与真实交易所费率细则。
- 回测/模拟结果**不代表未来表现**，也不构成任何投资建议。
- 智能问答只解释规则与指标、分析已发生的表现，不预测收益；**AI 调参只产出参数提案，永远要人工点「确认入库」才写策略库**，且只改白名单参数（乘数、最小变动、滑点是锁死的）。
- 环境分析里的「恐慌指数」用**20 日年化已实现波动率 + 近一年滚动分位**近似（akshare 没有稳定的 CBOE VIX 源），页面上明确标注了这一点，不要当 VIX 读。
- 环境分析依赖公开数据源，某个源抓不到时只标「不可用」，**不会编数字**；模型也会被要求只说数据里有的东西。
- SimNow 连接目前**只连接与订阅行情，不会发送任何委托**。要进入实时策略交易，还需补 5 分钟 bar 聚合、委托/成交/持仓状态机、断线重连与柜台对账。
